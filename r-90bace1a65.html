요청 정리와 장소 홍보 제작 방식
ONECUE에는 어떻게 붙일까?

결론: 옵션 1·2의 공통 입력은 보강하고, 장소 홍보 방식은 필요한 건에서 선택해서 쓴다.
지금은 옵션 3을 새로 만드는 것보다 기존 흐름의 역할을 분리하는 편이 적절합니다. 이 결론은 Codex 제안이며, Claude 최종 합의는 아직 아닙니다.

1. 두 방식의 역할이 다릅니다

구분요청 정리 틀Artlist X Astra 방식
정하는 것누구에게 무엇을 왜 보여줄지, 꼭 지킬 것과 맡겨도 되는 것실제 장소 사진을 바탕으로 장면·카메라·음향을 설계하고 영상으로 만드는 방법
알맞은 범위상품·서비스·장소 광고 공통실제 공간과 방문 경험이 중요한 장소 홍보
남겨야 할 결과원문, 목표, 자료, 필수·금지, 재량, 판단 기준, 각 정보의 출처검증한 장소·사진, 참조 이미지 연결, 장면 설계, 생성 지시문, 음향 계획
그대로 강제하면 생기는 문제불필요한 입력 항목이 늘어날 수 있음모든 광고를 빠른 공간 소개로 만들고 옵션 2의 모델 재량을 없앨 수 있음

원문: Artlist X Astra Prompt. 브라우저에서 원문을 확인했습니다. 아래 내용은 원문 실행이나 성능 검증이 아니라 ONECUE 적용을 위한 해석입니다.

2. 현재 옵션과 맞는 부분·충돌하는 부분

현재 brief_writer.py는 옵션 2에서 컷 목록을 쓰지 않고, 영상 모델이 컷과 카메라를 설계하도록 합니다. 기본 연출에는 속도감과 멀티앵글 요구가 있습니다. 반면 Notion 방식은 시간대별 장면과 카메라를 미리 지정합니다. 둘을 그대로 합치면 지시가 충돌합니다.

  • 옵션 1: 상세 장면 설계 흐름에 장소 홍보 방식의 자료 확인·참조 연결을 활용하기 좋습니다.
  • 옵션 2: 실제 장소 보존, 출처 확인, 제품·간판 정확성 같은 조건을 가져옵니다. 컷 목록은 기본으로 넣지 않습니다.
  • 공통: 라이브러리에서 의뢰와 맞는 기획·연출 카드를 먼저 찾고, 부족한 근거만 추가 조사합니다.

컷을 미리 설계하는 것과 영상을 한 번에 생성하는 것은 별개입니다.
상세 콘티를 만들어도 한 번에 생성할 수 있고, 짧은 브리프로 시작해도 결과에 따라 구간별 보완을 할 수 있습니다. 특정 도구의 지원 길이·참조 수·음향은 실행 시 공식 설정으로 확인해야 합니다.

3. Notion에서 가져올 것

  • 실제 자료 우선: 지점·장소·건축·간판·상품을 확인하고, 확인된 정보와 추측을 분리합니다.
  • 참조 이미지 역할 구분: 어떤 이미지가 어떤 장소·제품·인물의 기준인지 기록합니다.
  • 장면의 목적: 단순 예쁜 화면 대신 방문하고 싶은 이유를 보여줍니다.
  • 안정적인 움직임: 복잡한 행동을 겹치지 않고 인물 동작·시선·카메라 방향을 명확히 합니다.
  • 음향의 연속성: 한 번 생성할 때와 컷별 생성할 때 모두 음악이 장면마다 끊기지 않게 계획합니다.
  • 비용 통제: 승인한 생성 범위와 재생성 허용 범위를 구분합니다.

기본값으로 강제하지 않을 것

원문의 20초·가로형, 약 10컷·여러 장소, 모든 컷의 카메라 이동, 사람 노출 비율, 별도 엔드카드 금지는 해당 제작 방식의 선택입니다. 광고 전체의 규칙이나 모델의 기술적 필수 조건으로 저장하면 안 됩니다. ONECUE의 세로 광고·제품 광고·정적인 연출·엔드카드와 충돌할 수 있습니다.

4. 단계별 연결안

단계하는 일과 라이브러리 사용
제품·자료 확인원문과 사진에서 확인되는 사실을 정리. 광고주 입력 / 자료 관찰 / AI 추정 / 모름을 표시.
전략·콘셉트목표와 제품 톤에 맞는 서로 다른 기획 카드를 찾아 5개 방향 제안. 초 단위 구성·제작 지시문은 제외.
구성·각본선택한 방향을 장면 흐름으로 구체화. 옵션 2에서는 상세 컷을 강제하지 않고 핵심 조건으로 전달.
콘티·생성 준비필요한 시각 참조, 장면·카메라 기법, 제품 일관성, 생성 방식 결정. 장소 홍보 방식은 여기서 선택 적용.
검수·학습쓴 카드 ID, 적용 이유, 실제 결과, 실패 원인을 기록. 성공 여부를 확인하기 전에는 검증된 기법으로 승격하지 않음.

5. Claude 협의 상태

기존 Head 의견(seq453): 광고주 입력칸을 늘리지 않고 자료 확인 뒤 내부 요청 정리를 보강. 옵션 1·2 공통 입력, 원문 보존, 출처 구분, 외부 비공개에 동의했습니다.

새 비교안(seq457): 회신 대기. 공통 요청 정리 + 장소 홍보 선택형 방식, 옵션 3 보류, 상세도와 생성 단위 분리 의견을 전달했습니다. 전달 기록은 있으나 읽음·동의를 확인한 것은 아닙니다.

6. 받은 영상, 어디까지 분석했나?

정밀 분석이 끝나지 않은 자료는 있습니다. 영상 정보 수집, 정지화면 표본 확인, 연속 재생·음향까지 검수한 분석을 같은 완료 상태로 취급하면 안 됩니다.

확인 범위현재 확인한 것해석
제작사 다운로드 목록118행: downloaded 112, exists 5, failed 1파일 수령 기록입니다. 117편 정밀 분석 완료라는 뜻이 아닙니다. 파일 존재·중복은 별도 대조 필요.
수집 영상 카드기존 작업 기록: 29개 카드, 39개 작품 근거시각 표본 기반. 카드 본문에도 연결 동작·음향 미검수 표시가 있습니다.
장르 카드기존 작업 기록: 20개 카드짧은 구간 4fps 표본 기반. 전체 영상 정밀 분석으로 세면 안 됩니다.
incoming활성 폴더 영상 0개. _rejected 안 영상 2개. 안내·이미지·JSON 별도.받은 자료 전체가 여기 남아 있는 구조는 아닙니다. 제외된 영상은 분석 대기와 분리.
전체 미분석 편수미확정기존 169/94 집계와 이번 118행 목록은 범위가 다릅니다. 분석 파일 이름만으로 완료 판정하지 않고 작품 ID·영상 경로·검수 근거를 대조해야 합니다.

7. 다음 반영 순서

  1. Head와 옵션별 입력·연출 범위를 확정합니다.
  2. 요청 정리와 단계별 카드 검색 조건을 공통으로 연결합니다.
  3. 장소 홍보 방식은 맞는 의뢰에만 선택 적용합니다.
  4. 영상 재고와 검수 근거를 작품 단위로 대조해 정확한 미분석 목록을 만듭니다.
  5. 대표 의뢰에서 사용 카드와 결과를 검증한 뒤 정본에 반영합니다.
이 페이지는 검토용 신규 파일입니다. 기존 페이지·사이트 코드·DB·정본을 덮어쓰지 않았고 유료 생성도 실행하지 않았습니다.
