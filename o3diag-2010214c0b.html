한 줄로

병목 다섯 가지

  1. 단계마다 새 세션 — 조사·설계·검토·그림·영상·후반이 각각 새로 시작해 지시서(OPTION3_RUNNER.md)·플레이북·조사 자료·카드를 매번 처음부터 다시 읽음. 시간과 토큰이 같이 샘.
  2. 「막힘 → 다시 쓰기」 반복 — 검토가 막으면 설계 전체를 다시 쓰고 다시 검토. 투썸 설계 5번, 롤렉스 6번.
  3. 확인 장치의 오판 — 4건 멈춤 9번 중 6번이 확인 장치 자체의 잘못:
    • 카메라 움직임을 「동작」으로 셈
    • 「제품 시트에 손이 없다」를 모순으로 봄
    • 「참조 그림 파일이 아직 없다」(원래 다음 단계에서 만듦)를 규정 위반으로 봄
    • 실물 사진이 있는데 「없다」(폴더가 한 단계 깊음)
    • 공식 홈 화면의 다른 시계와 비교해 맞는 시트를 「다르다」
    • 비교용으로 일부러 넣은 예전 변기솔을 오류로 봄
  4. 후반 항목이 생성 전 검토로 새어 들어옴 — 끝 장면 로고 파일 설명·공식 문구 자르기로 asdf 생성이 막힘. 후반에서 고칠 일.
  5. 실행기가 파일 위치·이름을 제멋대로 — 그림을 건 폴더 바로 아래·대문자 이름으로 저장 → 확인 장치가 못 찾음.

그리고 Head(저)가 도는 중에 끊고 고치고 다시 이어 붙여, 4건이 서로 다른 판의 엔진으로 돌았습니다. 그래서 오늘 결과로는 엔진의 진짜 실력을 판단할 수 없습니다.

내일 할 것 (제안 · Dan 확인 뒤)

  1. 재기 — 실행기가 단계마다 시간·토큰을 기록하게 함(출력 형식만 바꿈).
  2. 잘 됐던 것과 나란히 — 환타 v6(「참 잘 나왔다」)·오아 오전 판(66분)과 지금 엔진을 단계·확인·시간·토큰으로 비교.
  3. 줄이기 — 설계 세션 하나(opus: 조사~프롬프트) + 생성 세션 하나(sonnet: 그림~후반). 확인 지점에서 멈췄다가 같은 세션을 이어서 부름(--resume · 다시 읽지 않음).
  4. 막는 건 셋만 — 제품 시트 ↔ 실물 · 영상 속 제품 · 금지 다섯 가지. 나머지 판정은 기록만 하고 진행.
  5. 확인 장치는 시험 뒤에만 — 새 확인은 지난 5건(오아·투썸·나디아·asdf·롤렉스)에 먼저 돌려 오판이 없을 때만 켬.
  6. 파일 자리는 코드가 정함 — gen/ 고정 이름.
  7. 돌릴 때는 손대지 않음 — 한 건 돌려 숫자로 비교한 뒤 나머지.
